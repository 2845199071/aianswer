# PC 侧准确率基准

不必上手机就能估模型水平。用的是与 App 完全相同的 ChatML 模板，
`LlamaCompletion` 走原始 prompt（不套 chat 模板），所以结果可迁移。

```bash
npm i node-llama-cpp
# 模型自行下载到 models/，例如
# https://www.modelscope.cn/models/Qwen/Qwen2.5-1.5B-Instruct-GGUF
node bench.mjs models/q15.gguf              # 基础 15 题
node bench.mjs models/q15.gguf ./cases_hard.mjs   # 难题 10 题
```

2026-10-29 实测（x86 8 线程，仅作相对参考）：

| 模型 | 基础题 15 道 | 难题 10 道 | 中位耗时/题 | 体积 |
|---|---|---|---|---|
| Qwen2.5-0.5B Q4_K_M | 80% | 70% | 30 ms | 469 MB |
| **Qwen2.5-1.5B Q4_K_M** | **100%** | **90%** | **50 ms** | **1.06 GB** |
| Qwen2.5-3B Q4_K_M | 100% | 90% | 73 ms | 1.96 GB |
| Qwen3.5-2B Q4_K_M | 93% | 80% | 66 ms | 1.19 GB |
| MiniCPM5-2B Q4_K_M | 53% | 40% | 57 ms | 1.45 GB |

**结论：1.5B 是这个任务的最优点，更大的模型没有换来准确率。**

- Qwen2.5-3B（同系列放大）：准确率与 1.5B **完全持平**，但慢 46%。唯一好处是错的题不一样。
- Qwen3.5-2B（新一代）：反而更差。它面向通用/多模态/Agent 优化，中国职业资格考试这类
  基础知识的密度不如 Qwen2.5。
- MiniCPM5-2B：大量输出 `<|im_end` 直接结束，它不认「答案：」这种 prompt 结构，
  需要单独适配模板，而且基础题只有 53%，不值得。

注意：第一题总是特别慢（几千毫秒到十几秒），那是权重首次被真正读进内存；
后续题命中页缓存，才是稳态速度。手机上稳态约为 PC 的 5~10 倍耗时。

**这个结论只对"中文职业资格考试型单选"成立。** 换成数学推导、代码、长文本理解，
更大的模型会明显更好——那种场景应该走在线模型。

### 跨行业复测（`cases_mixed.mjs`，18 题覆盖 10+ 行业）

之前 25 题全是电工/安全生产，怕结论有偏。补了一组跨行业常识：

涵盖 会计恒等式、护理心率、民法典离婚冷静期、HTTP 状态码、鲁迅原名、水沸点、
人体最大器官、光速、质数、宪法年份、企业所得税率、GB 换算、教师资格学历、
维生素 A、通货膨胀、热胀冷缩、Word 快捷键、法定成年年龄。

| 模型 | 结果 | 中位耗时 |
|---|---|---|
| Qwen2.5-1.5B | **18/18 = 100%** | 43 ms |
| Qwen2.5-3B | **18/18 = 100%** | 73 ms |

**跨行业广度不是小模型的短板**——各行业的基础常识它都记得住，1.5B 和 3B 打平。
真正的短板是**深度专业细节**（具体准则条款、疑难病例、复杂计算），那种题 3B 也救不了，得走在线。

所以选型结论不变：**1.5B 就够，3B 白慢 70%。**
