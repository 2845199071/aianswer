> 来源项目：`刷题助手-安卓/源码/刷题助手-源码/quizbank`（1201 题实测题库验证过的实现）

## 一、从刷题助手搬过来的逻辑

| 文件 | 复用的关键方法 | 作用 | 为什么值得搬 |
|---|---|---|---|
| `Importer.java`（784 行） | `importFile()` / `buildTable()` / `detectHeader()` / `guessLayout()` / `finish()` / `parseAnswer()` | 把 xlsx / csv / tsv / txt / docx / json 统一转成内部题库 JSON | 支持**表头不在第一行**（自动在前 30 行里找真正的表头）、表头同义词（题干/题目/标题/试题、正确答案/答案）、答案支持 `ABCD` 连写 / `A,B` / `正确` / `√` / 直接写选项原文、判断题没写选项自动补「正确/错误」 |
| `TextParser.java`（232 行） | `parse()` | 纯文本/Word 按「题号 + 选项行 + 答案行」切题 | 兼容 `1、` `1.` `（1）` `第1题` 四种题号；`A．甲 B．乙` 挤一行也能拆；页脚页码、标题行自动跳过 |
| `XlsxReader.java` / `DocxReader.java` | `read()` / `paragraphs()` | 不依赖 POI，直接解 zip + XML | 体积小、无第三方依赖，APK 不膨胀 |
| `Matcher.java`（549 行） | `norm()` / `symSig()` / `matchBest()` / `findTextIndex()` / `buildVariants()` | 题干匹配 + **答案文本定位** | 这是整套逻辑里最值钱的部分，见下节 |
| `BankStore`（124 行） | 多题库文件 + meta | 存储结构 | 每份一个 JSON，不需要存储权限；本次改成**所有题库合并检索** |

### 1.1 `norm()`：归一化的细节决定成败

- 全角转半角、去空白标点、小写
- **保留 `>` `<` `≤` `≥`**：`直流电流>1000mA` 和 `直流电流≤1000mA` 是两道不同的题，一律剥标点会让它们归一撞车、互相抢分
- 题号只有「数字 + 分隔符」或「剩余正文 ≥6 字」才剥：`3年` `20万次` 这类选项开头的数字是内容，不是题号（剥了会让 A=3年 / B=5年 全变成「年」，定位永远命中第一个）

### 1.2 `symSig()`：正负号不能丢

`+15%` 与 `-15%` 归一后都是 `15%`。只按相似度定位会点到相反的那个选项。做法是额外提取「正负号 + 比较符」签名，签名不一致直接跳过该候选。

### 1.3 `matchBest()`：多切分投票

读屏拼出来的题干常夹着上一题残留、说明文字或标题。把「最后一句 / 最后两句 / 整段」几种切分都拿去匹配，取分数最高且更短的那个——夹了噪声相似度会掉，这一步能把切分错误纠回来。

### 1.4 `findTextIndex()`：按**文本**定位，不按字母

题库答案是 `B`，但屏幕上选项顺序常被打乱（同一份卷子两次打开顺序都可能不同）。直接按字母点就是错。正确做法：

```
题库答案字母 → 取该字母对应的选项原文 → 在屏幕选项文字里找最像的那个 → 取屏幕上的字母
```

刷题助手实测「打乱选项 100 次，97+ 次能定位正确」，这是本功能可用性的根基。

### 1.5 `buildVariants()`：同题干多版本合并

导入的题库里常见「题干完全相同、答案不同」的多版本（不同出题角度，两种说法都对）。策略是**把各版本答案文本取并集**，刷题时看屏幕实际出现哪一个。两条保护：选项集合必须有交集才合并（否则是两道不同的题）；答案本来就一致则不合并。

## 二、与 AI答题 答题流程的衔接

### 2.1 判定顺序（`QService.tick()`）

```
读屏（题干 + 选项 + 屏幕字母）
        │
        ├─① 自选题库（开关开 && 已导入 && 不是手动「识别」）
        │     命中且能在屏幕定位 → 答案 = 题库答案文本在屏幕上的字母
        │                         0 次网络调用，毫秒级，不写本机记忆库
        │     命中但定位不到     → 不占用结果位，继续往下走，题库答案作对照
        │
        ├─② 本机记忆库（Record.bank，AI 答过的题缓存）
        │     命中 → 0ms 返回（有分歧的题不静默命中）
        │
        └─③ AI
              投票（≥2 在线模型）> 题型路由 > 在线/本地优先
              结果写本机记忆库 + 本场记录
```

### 2.1.1 三层的关系：短路，不是并列

| 组合 | 会不会打架 | 说明 |
|---|---|---|
| 自选题库 × 题型路由 | **不会** | 题库命中直接 `return`，`AnswerEngine` 根本不被调用；路由只在题库未命中时才有机会 |
| 自选题库 × 多模型投票 | **不会** | 同上，投票也在引擎内部 |
| **多模型投票 × 题型路由** | ✅ v7.2.8 起共存 | 路由先决定走哪条线，投票只作用于在线线路；判为本地的不烧投票额度 |
| 路由 × 单通道 | 不冲突，但**不生效** | 路由要求在线和本地都可用；只配一条时开关亮着也没用 |

设置页会把三种「看起来开着、其实不工作」的情况说清楚：只有一条通道可用时路由说明变橙色提示「当前只有在线/本地通道 · 题型路由暂不生效」；投票与路由同时开启时提示「判为在线的题才投票，判为本地的不烧额度」。

### 2.1.2 自选题库命中但定位不到：降级问 AI

早期实现是「命中即返回」，即使答案文本在屏幕上找不到也占着结果位，导致 AI 没机会兜底。v7.2.6 改为：

- 题库答案**不占用结果**，继续走 ② ③
- AI 出结果后，在答案区追加一行「题库：A（未定位到屏幕）」作对照
- AI 也失败时，退回题库答案并给 0.4 置信度（低于阈值 → 不自动点击）
- 对照写进 `detail` 而不是 `updateWhy`：解析回调会把 why 覆盖掉


### 2.2 为什么自选题库排在本机记忆库前面

自选题库是**用户上传的权威答案**（教材/官方题库），本机记忆库是 AI 自己答过的历史结果。用户明确要求「先查自选题库，未命中再调用 AI」，所以顺序固定，设置项只控制「查不查」，不改变顺序。

### 2.3 为什么不写本机记忆库

自选题库命中若写进 `Record.bank`，会污染「题库记住 N 题」这个统计（用户以为那是 AI 学到的），并且两套答案打架时无法区分来源。所以自选题库命中只记「本场记录」（用于复制答案、统计），不写长期记忆库。

### 2.4 手动「识别」= 强制复核

悬浮球「识别」按钮会置 `verifyBank=true`，此时**跳过自选题库和本机记忆库**，直接问模型——这是用户主动要求「这题题库答案对不对」的场景，必须走 AI。

### 2.5 定位失败的保护

题库答案文本在屏幕上找不到（相似度 <0.75）时：
- 显示题库字母 + 提示「屏幕上没找到对应选项文字，请核对后再点」
- 置信度按 0.4 计，低于阈值 → **不自动点击**

点错比不点更亏，这条沿用 AI答题 原有阈值机制。

## 三、本次对搬来的逻辑做的三处加固

原实现面向「固定卷子 + 固定题库」，AI答题 面对任意页面，必须补三刀：

| 加固 | 原问题 | 做法 |
|---|---|---|
| **题干下限 `MIN_STEM = 0.45`** | 屏幕选项与题库恰好一致、题干完全不同时（同一份卷子相邻题、同批选项的系列题），选项满分把总分抬过 0.60 阈值 → 误命中 | 题干相似度 <0.45 直接判「没有」，选项再像也不认 |
| **强题干豁免选项分** | 题干 100% 相同但选项写法不同（`12V` vs `十二伏特`），选项分为 0 → 59 分被拒 | 题干 ≥0.95 时不再要求选项分 |
| **多份题库合并检索** | 原设计一次只用一个题库，用户要来回切 | 所有已导入题库合并成一个数组加载；删除某份后自动重建 |

## 四、数据格式与存储

```json
[{"t":"单选","q":"题干","a":["B"],"o":{"A":"…","B":"…"},"e":"解析"}]
```

- 存储：`/data/data/com.dsh.aianswer/files/selfbanks/<id>.json` + `<id>.meta.json`（名称/题数/导入时间）
- **索引**：`SharedPreferences("selfbank_index")` 记录导入过的题库，用来发现「文件丢失」（被清理工具删掉时界面显示「文件丢失，请重新导入」，而不是装作没导入过）
- 上传：系统文件选择器（SAF），**不需要存储权限**；文件只在内存里转一次 JSON

## 六、已知问题

1. **自选题库文件在一次重装后消失**（`files/selfbanks` 变空，但同目录下 1.06GB 的本地模型文件仍在，`SharedPreferences` 里的在线配置与调用计数也都在）。已加索引把这种情况显式标为「文件丢失」，但**根因未定位**。下一步排查方向：`add()` 后立即读回校验、把导入改成「先写临时文件再 rename」、观察是否为第三方清理工具针对新建目录的行为。
2. 大题库（2000+ 题）首次打开自选题库弹窗会加载并合并 JSON，约 100~200ms，暂未做进度提示。
3. 上传入口用 SAF，部分机型选择器启动要 3~5 秒（系统行为，已在 UI 上不阻塞）。
