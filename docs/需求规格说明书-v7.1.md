## ① 项目概述

在现有「读屏 → 出答案」能力上，把 v7.0.4 的"一次性答题工具"升级为**带记忆、可纠错、可自查**的答题系统：答过的题沉淀成本地题库，答错的题自动进错题本，模型选谁由题目类型自动决定，用户对答案有最终裁决权。

要解决的核心问题：现有题库只会"覆盖写"，同一题两次不同答案会静默互相冲掉，用户既看不见也改不了。

## ⑥ 关键设计：题库与冲突

### 6.1 存储结构升级

现结构：`bank.<md5(sig)> = "B"`（只能覆盖，无法存元数据）
新结构：`bank.<md5(sig)> = JSON`

```json
{
  "a": "B",              // 当前答案
  "src": "手动|智能-1.5B|在线-智谱",
  "conf": 95,
  "hits": 5,             // 命中次数
  "ts": 1762700000000,   // 最近更新
  "locked": true,        // 用户手改过 = 金标准
  "cf": [{"a":"C","src":"在线-智谱","ts":1762700000000}]
}
```

兼容：读到旧的纯字符串值 → 视为 `{"a":"B","src":"旧版本","hits":1}`，首次写入时自动迁移，不清库。

### 6.2 冲突处理策略（核心）

**仲裁优先级，从高到低：**

| 优先级 | 情况 | 行为 |
|---|---|---|
| 1 | 题库 `locked=true`（用户手改过） | 直接出题库答案；模型结果不同只在悬浮窗角落标「模型持异」，**永不覆盖** |
| 2 | 题库命中且与本次模型答案一致 | `hits+1`，正常出答案 |
| 3 | 题库命中但与模型答案不同 | **不覆盖**。本次显示高置信一方（同信则显示题库），同时把模型答案写入 `cf[]`；悬浮窗显示黄色角标「有分歧」 |
| 4 | 冲突累计达 2 条且来源不同、答案一致 | 悬浮窗出现「是否更新题库？」提示，用户点才更新，**绝不自动改写** |
| 5 | 题库无此题 | 写入首次答案，`src=来源`，`hits=1`，`locked=false` |

**多选特例**：字母集必须**完全相等**才算一致。`ABD` 与 `AB` 视为不同答案（走冲突），不做包含关系合并——漏选/多选在考试里都是错，自动合并会掩盖真实分歧。

**"同一问题"的判定**：沿用现有 `sig`（题干+选项文本规范化后 MD5）。注意：选项顺序不同会被当成新题，这是可接受的保守策略【AI建议：不做选项顺序归一化，避免把"选项顺序变了但答案字母含义不同"的题误并】。

### 6.3 错题本判定

收录条件（满足任一）：
1. 用户在题库里**改过**的答案（→ 原来那个答案算错，记一条错题）
2. 复核/投票出现**两路不一致**且用户最终采纳了另一路
3. 模型置信度低于阈值且**用户手动点了别的选项**（需读取无障碍点击事件，V7.2 才能做，V7.1 先只做 1、2）

错题本 = 题库的一个视图（`wrong=true` 标记），不是独立存储，避免两份数据打架。

### 6.4 统计

在现有 `Record.Stats` 上增加：
- 题库命中率 = 题库命中数 / 总答题数
- 各来源正确率（在线 vs 本地）——需要错题标记才能算，V7.1 只统计"各来源出题数"
- 冲突题数、错题数

## ⑦ 关键设计：简洁解析

| 项 | 规格 |
|---|---|
| 触发 | 设置里「出答案附一句解析」开关，**默认关**；关闭时悬浮窗有「解析」小按钮手动触发 |
| 在线生成 | `max_tokens=48`，system 追加「只用一句话说明依据，不超过 30 字，不要复述题目，不要分点」 |
| 本地生成 | 仅 1.5B 及以上档位允许；`max_tokens=24`；0.5B 直接返回「本档位不支持解析」 |
| 显示长度 | 悬浮窗内**最多 2 行**（约 28 字），超出截断并加「…」 |
| 展开 | 点击解析文字 → 小弹窗，最多 5 行，可滚动 |
| 耗时提示 | 解析是第二次推理，会多 0.5~2s；悬浮窗先出答案，解析**异步补上**，不阻塞答案显示 |
| 落库 | 不入库（避免体积膨胀） |

## ⑧ 关键设计：自动路由（V7.2）

### 8.1 判定特征（命中任一「大」特征即走大模型，宁可大不小）

| 特征 | 判定方式 | 走哪 |
|---|---|---|
| 数学/计算 | 含 `= + - × ÷ ∑ √ % ^` 或「计算/求解/化简/面积/概率/多少倍/平均」 | **大模型（在线）** |
| 文言文/古诗文 | 含「之乎者也焉曰」或成对引号内古文片段或「下列句子中加点词」 | **大模型（在线）** |
| 长题干 | 题干 > 120 字 | **大模型（在线）** |
| 多选且选项多 | 多选 且 选项 ≥ 5 | **大模型（在线）** |
| 专业条文 | 含「法条第/条规定/应当/不得/临床/会计/税率」 | **大模型（在线）** |
| 常识短题 | 题干 ≤ 40 字 且 无上述特征 且 选项 ≤ 15 字 且 单选 | **小模型（本地 1.5B）** |
| 其他 | 兜底 | 小模型（本地 1.5B），若本地未加载则在线 |

### 8.2 降级链

```
首选在线（大） → 在线失败/熔断 → 本地旗舰 4B（已下载时） → 本地 1.5B → 报错
首选本地（小） → 本地未加载 → 在线 → 报错
```

### 8.3 可见性

- 悬浮窗来源行显示「路由：数学 → 在线」
- 设置里开关下方一行灰字：「短题/常识走本地，数学/文言/长题走在线」
- 用户可关闭自动路由，关闭后完全按现有「在线优先/本地优先」逻辑

## ⑨ 关键设计：多模型投票（V7.2）

### 9.1 前置条件（用户明确要求）

- 统计「已填 Key 且配置完整」的在线模型数 `readyCount`（复用 `Prefs.cloudReady`，含 6 家预设 + 自定义）
- `readyCount >= 2` 才允许开启；否则开关**置灰不可点**，副标题显示「需配置 2 个以上在线大模型（当前 N 个）」，点击弹出引导去在线配置
- 运行中若用户删了某个 Key 导致降为 1 个 → 自动关闭投票并弹一次性提示

### 9.2 与现有「复核」的关系（重要）

**投票开 → 复核自动灰掉**，两者互斥。理由：复核已是"两路对拍"，投票是"多路对拍"，叠加会变成 3~4 次调用，免费额度会被烧穿。这是本草案的强建议【AI建议：互斥，不做叠加】。

### 9.3 执行逻辑

- 参与模型：取 `readyCount` 中最多 3 个（按免费额度优先排序，智谱 → 千帆 → 魔搭 → 硅基 → 混元 → DeepSeek）
- 串行调用（本地 llama 单实例 + 避免并发限流），单路超时 8s，超时/失败不计票
- 计票：多数胜；平票取「免费优先 + 置信高」；全部失败 → 回退本地
- 结果标注：
  - 全票一致 → 绿色「3/3 一致」，置信提到 0.95
  - 2:1 → 黄色「2/3 一致」，置信 0.8
  - 三方全不同 → 红色「三方分歧」，**不自动点击**
- 成本提示：开关下方显示「每次答题消耗 N 次在线调用」

## ⑪ 关键设计：拟人点击（V7.1）

- 新开关 `swHumanClick`，**默认 false**
- 前置：自动点击开启时才可点，否则置灰
- 开启流程：点开关 → 弹确认窗「拟人点击会加入 80~200ms 随机延迟与轻微轨迹偏移，仅影响点击手感，不改变答案。是否开启？」→ 确认才生效
- 实现：现有 `dispatchGesture` 路径上插入随机延迟 + 起终点偏移 ±3dp
- 关闭后立即恢复直点

## ⑭ 适配问题专项（用户明确要求）

| 适配项 | 风险 | 对策 |
|---|---|---|
| 小屏（5.5" / 720p） | 题库列表 + 详情弹窗超高 | 弹窗最大高度 85% 屏高，内容 ScrollView；详情页题干区 maxHeight 40% |
| 系统字体放大（1.3x/1.5x） | 简介四行文字撑破卡片 | 简介用 `CardSub`（12sp）固定，卡片 `wrap_content` 高度，不做固定高 |
| 横屏 | 弹窗被压扁 | 弹窗锁竖屏（`screenOrientation` 不变，弹窗跟随 Activity），内容滚动 |
| 题库规模 | 5000+ 题时列表卡顿 | 列表用 RecyclerView + 懒加载（不用 ScrollView 全量 inflate） |
| SharedPreferences 体积 | 8000 题后读写变慢 | 超过 8000 题弹出提示，v7.3 迁 SQLite |
| 内存 | 4B 模型 2.3G + 投票 3 路 | 投票串行执行；切换模型时先 unload 再 load；低内存机（<6G）默认不推荐 4B |
| 网络不稳 | 投票某路超时拖慢整体 | 单路 8s 超时，先到先计票，超时不算 |
| 熔断 | 投票时某厂商限流 | 复用 `CloudSolver.cooling()`，熔断厂商不参与计票 |
| 无障碍兼容 | 部分 ROM 点击事件不同 | 沿用现有 `dispatchGesture` 优先策略 |
| 后台 | 国产 ROM 杀进程 | 沿用现有前台服务保活 |
| 无障碍读屏 | 新开关需可被 TalkBack 朗读 | 所有 Switch 加 `contentDescription`，说明副标题合并进 `contentDescription` |
| 深色模式 | 现有锁死白底 | 本次继续保持白底锁死策略，不加深色模式（避免与现有 token 冲突） |

## ⑮ UI 一致性约束
